# AGENTS.md — AgentConnect-PC AI Agent Operations Manual

> This file is written for AI agents. Humans should start with [README.md](README.md) or [README.en.md](README.en.md). If you do not know this project, read this file completely before acting.

## 1. Mission and mental model

AgentConnect-PC is a **controller-side** application for giving AI agents hands-on access to remote Windows PCs through MCP and Tailscale.

- **Controller**: the computer where Claude Code, Codex, Cursor, ZCode, OpenCode, or another agent runs.
- **Controlled PC**: the remote Windows computer. It runs `windows-mcp-server.exe` on port 8808 and has a visible minimized console window.
- **Transport**: Tailscale WireGuard network (`100.x.y.z`) plus streamable HTTP MCP.
- **Authentication**: a target-specific Bearer token generated by the controller. A Tailscale single-use Auth Key is used only to join a target to the controller's tailnet.
- **Controlled tools**: windows-mcp exposes 20 tools including screenshots, mouse/keyboard input, files, PowerShell, registry, processes, and notifications.

The safe default is: **controller generates everything, target owner only runs one installer, controller verifies the target, then the AI agent uses the MCP endpoint**.

## 2. Read-before-action rules

1. Run `git status --short --branch` before editing or deleting anything.
2. Never read, print, copy, or transmit `my-targets/*.env`, Auth Keys, Bearer keys, Tailscale management tokens, or generated `target-*` folders unless the user explicitly requested a specific authorized operation.
3. Never commit secrets. Before `git add`, run a secret scan and inspect `git status`.
4. Treat `build/`, `dist/`, `.build-venv/`, `release-staging/`, and downloaded release assets as local build state, not source.
5. When a file changes unexpectedly, stop and inspect `git log`, `git diff`, and the current file before overwriting it. Multiple sessions may work on this project.
6. Only operate a controlled PC with its owner's explicit consent.
7. Payments/transfers are forbidden. Deletion requires owner confirmation. System settings require recording the old and new values.
8. Screenshots, clipboard, notifications, files, and terminal output may contain sensitive data; do not exfiltrate them.

## 4. Standard workflow A: new target

The preferred controller workflow is the CLI or GUI.

### CLI

```bat
agent-connect-cli.exe new <nickname> --auth-key tskey-auth-...
agent-connect-cli.exe wait <nickname> --timeout 3600
agent-connect-cli.exe snippets <nickname> --client all
```

If a Tailscale management token is configured at `my-targets/tailscale-api.env`, `new` can generate a single-use Auth Key automatically:

```text
TSMGMT_TOKEN=tskey-api-...
```

If the token is absent, generate a single-use key in the Tailscale admin console and pass it explicitly. Never put the token or key in README, source, Git, chat, or a public issue.

### GUI

1. Run `agent-connect-gui.exe`.
2. Click “生成目标包”, enter the nickname and single-use Auth Key.
3. Send the complete generated `target-<nickname>/` folder to the target owner.
4. Click “等待并连接”.
5. After success, use “复制 MCP 配置” to configure the agent.

### Target owner

The target owner should only:

1. extract the folder;
2. double-click `install_on_target.bat`;
3. approve administrator prompts;
4. keep the minimized `windows-mcp server` window open.

The target owner should not need to copy IPs, Bearer keys, Auth Keys, or edit JSON.

## 5. Standard workflow B: existing target

1. Run CLI `status` or the `tailscale` MCP `ts_status` tool.
2. If the peer is offline, distinguish power/sleep/network from service failure before changing anything.
3. Run `ping <100.x IP>` or `ts_ping`.
4. Run MCP handshake verification only after the tunnel is reachable.
5. A 401 means Bearer mismatch; do not regenerate blindly. Inspect the correct local target env with care.
6. A ping timeout means Tailscale/firewall/target availability. A ping success plus MCP timeout means target service or port 8808.

## 6. AI client connection model

The endpoint is:

```text
http://<target-tailnet-ip>:8808/mcp
Authorization: Bearer <target-env-BEARER>
```

- Native HTTP clients use URL + Authorization header.
- stdio-only clients use `mcp-remote` with `--header`.
- ZCode uses the existing `mcp-remote` pattern in its user config.
- Do not hand-type Bearer values when `agent-connect snippets` can print a correct snippet.

## 7. Topology variant: server as controller (Linux/Windows Server)

The controller is simply "whatever runs the agent and can reach the target over the tailnet". A cloud server/VPS is a valid controller for operating the user's **own local Windows PC** — typical case: a 24/7 server agent runs long tasks on the user's desktop while they are away.

Requirements and steps (Linux):

1. Install Tailscale and join the controller's tailnet: `tailscale up --authkey <single-use key>` (or interactive login).
2. Optional management CLI from source: `python -m agent_connect.cli status|new|wait|snippets` (stdlib only, works headless; needs `tailscale` on PATH). The Windows exe assets and the Tkinter GUI do **not** apply to Linux.
3. Set up the local PC as a standard controlled target (offline exe + installer, or `new` a bundle and send it to the user themselves).
4. Point the server agent's MCP client at `http://<target-100.x>:8808/mcp` with the Bearer header; add `100.64.0.0/10` (or the target IP) to NO_PROXY if the server uses proxies.
5. Verify: `tailscale ping <target>` then a raw MCP `initialize` returning HTTP 200 (copy-paste curl in README section 7).

Caveats an agent must know:

- The target PC must stay awake with the service autostart alive; sleep/lid-close/RDP-disconnect blinds GUI tools — this is a machine state issue, not a service failure.
- Sandboxed platforms that forbid VPN installs: Tailscale degrades to DERP relays over TCP 443; if that is also blocked, fall back to frp/own tunnel for port 8808 and manage encryption/auth yourself.
- **Trust inversion**: the Bearer key lives on the server. Server compromise equals full control of the target PC — harden SSH, prefer a Tailscale ACL limiting the server to target:8808, rotate keys on any suspicion.
- All project red lines (no payments, deletion confirmation, settings logging, no secret exfiltration) apply to server-side agents unchanged.
- When documenting or scripting this topology, treat the server as the controller in every workflow above; nothing else in sections 4-5 changes.

## 8. Build and release model

The public product name is **AgentConnect-PC**. The GitHub repository is `agent-connect-pc` after the release rename.

Two controller release assets are required:

- `agent-connect-cli-windows-x64.zip`
- `agent-connect-gui-windows-x64.zip`

Each package contains its controller executable, the controlled-side offline exe, and installation templates. The target executable is a release input and should be downloaded from the existing Windows-MCP release before building:

```bat
python build_controller.py --clean --target-exe release-assets\windows-mcp-server.exe
```

The builder creates:

```text
release-staging/agent-connect-cli-windows-x64.zip
release-staging/agent-connect-gui-windows-x64.zip
```

Before release:

1. compile `agent_connect`;
2. run CLI help/version/status;
3. run both frozen EXEs (`--help` for CLI, launch GUI);
4. inspect zip contents and hashes;
5. scan zip contents for `tskey-`, `BEARER=`, `TSMGMT_TOKEN=`, real IPs, customer names, and `.env` files;
6. verify the GitHub tag/release contains exactly the two controller zips and release notes;
7. never upload `my-targets`, target zip folders, `.build-venv`, or PyInstaller build caches.

## 9. Cleanup policy

Safe to remove after a successful archive and release:

- `.build-venv/`
- `build/`
- `dist/`
- `release-staging/`
- downloaded `release-assets/`
- generated `target-*` folders and zips
- screenshots and temporary test output
- obsolete protocol/test scripts that are no longer referenced by CLI, GUI, README, or build scripts

Keep source code, packaging specs, build scripts, the controlled installer, Tailscale MCP, README files, LICENSE, and this manual.

## 10. Security and operations

- `tailscale up/down` may require Windows UAC; an AI agent cannot click the secure desktop. Ask the owner to confirm.
- The minimized target console is the visible stop control. Closing it stops remote control.
- Never use `--allow-insecure-remote` to bypass windows-mcp authentication.
- Do not directly kill the current MCP process while rotating a remote Bearer key. Write a delayed target-side script, start it detached, then verify the new key and old-key 401.
- If a secret ever enters Git history, remove it with a reviewed history rewrite and force-with-lease, then rotate the secret immediately.
- Before changing a firewall or system setting, record the old state and the rollback command.

## 11. Agent reproduction checklist

When an agent is asked to reproduce this project from a fresh clone, it should:

1. read this file and both README language variants;
2. identify Windows x64 and verify Tailscale availability;
3. download the controlled exe release asset into `release-assets/` (or receive `--target-exe`);
4. create a Python 3.14 PyInstaller environment only if building from source;
5. run `build_controller.py --clean --target-exe ...`;
6. inspect and hash both zip assets;
7. run the CLI frozen help/version/status and launch the GUI;
8. explain to the human that the target owner needs only the generated folder and installer;
9. never expose secrets or commit generated target folders;
10. report what was tested, what was not tested, and any missing Tailscale login/permissions.

If a requirement is ambiguous, inspect source and current GitHub release state rather than guessing.
